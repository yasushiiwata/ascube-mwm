## 3. AccessionNumber（MWM連携用コード）

### 3-1. 採番規則（実データで検証済み）

項番130〜149 が **`AccessionNo（MWM連携用ｺｰﾄﾞ）`** の20枠。備考に規則が明記されています。

```
YYMMDD  BBBBB  AA  CCC        ※レイアウトは X(17) だが実データは 16 桁

受診日  受診番号 受診区分 検査識別

例: 2607010011010053
```

### 3-3. ⚠ 骨密度の枠がない

依頼項目フラグには **項番59「骨密度(駅前)」／項番60「骨密度(山科)」** があり、実データでも項番59 に `1` が立っています。**検査は依頼されるのに、MWM 用の番号が払い出されません。**

| 対応 | 内容 | 位置づけ |
|---|---|---|
| **短期（9/28 用）** | BRIDGE-Navi 側で同じ規則で自前生成：`受診日(YYMMDD) + 受診番号(5) + 受診区分(2) + 骨密度の検査識別(3)` | すぐ実装できる |
| **本筋** | **ヘルゼアに予備2〜7 の1枠を骨密度へ割り当ててもらう** | ベンダ改修。日数がかかる |

⚠ **短期案の前提：骨密度の「検査識別コード（CCC 3桁）」をヘルゼアに確認すること。**
勝手な番号を振ると、将来ヘルゼアが正式に払い出したときに**番号が衝突**します。フラグが存在する以上、内部には必ず定義があります。

`AccessionNumber` の VR は `SH`（16文字以内）。**16桁ちょうどなので収まりますが、余裕はありません。**17桁になる運用があるならレイアウト側の `X(17)` が正で、その場合は装置側の扱いを確認する必要があります。

## 4. ⚠ 当日の身長・体重は依頼電文に無い

依頼電文にあるのは**過去の測定値だけ**です。

| 項番 | 項目 |
|---:|---|
| 175 | 前回受診日 |
| 196 / 197 / 198 | 前回結果値：身長 / 体重 / BMI |
| 229 | 前々回受診日 |
| 230 / 231 | 前々回結果値：身長 / 体重 |

依頼電文は**受付時点**で生成されるため、当日の身長体重はまだ測っていません（項番32 に「身長体重」の依頼フラグがある＝これから測る）。

**設計方針**

1. **BRIDGE-Navi が「身長体重」ブースで記録した当日の実測値を使う**（`(0010,1020)` PatientSize ／ `(0010,1030)` PatientWeight）
2. 当日値が未測定なら **タグごと省略**（`onMissing: omit`）
3. ⚠ **前回値を今日の値として送らない。** 値の捏造にあたり CLAUDE.md 規則4 に反する

⚠ **ブースの巡回順は誘導アルゴリズムが決めるため、骨密度が身長体重より先になる場合がある。**「未測定なら省略」を必ず実装すること。

## 5. 患者氏名の構築（PN）

### 5-1. 実データで確認した事実

| 項番 | 内容 | 文字種 | 姓名の区切り |
|---:|---|---|---|
| 6 | カナ氏名 | **半角カナ** | **半角スペース（ASCII 0x20）** |
| 7 | 漢字氏名 | **全角** | **全角スペース（U+3000）** |

### 5-2. 変換手順

**BRIDGE-Navi 側（分割だけ。変換はしない）**

```
カナ氏名  "ﾔﾏﾀﾞ ﾀﾛｳ"   → 半角スペースで split → ["ﾔﾏﾀﾞ", "ﾀﾛｳ"]  ★半角のまま渡す
漢字氏名  "山田　太郎"   → 全角スペースで split → ["山田", "太郎"]
```

**SCP 側（PnEncoder。プロファイルで変わる）**

| 案 | PN |
|---|---|
| ① `ISO_IR 192` | `ヤマダ^タロウ=山田^太郎=ヤマダ^タロウ`（半角カナ→全角カナ変換あり） |
| ② `ISO_IR 192` | `=山田^太郎=ヤマダ^タロウ`（第1群を空に） |
| ④ `ISO_IR 13` | `ﾔﾏﾀﾞ^ﾀﾛｳ`（半角カナのまま・漢字を送らない） |

⚠ **全角化を BRIDGE-Navi 側でやってはいけません。**案④では半角カナのまま送るため、BRIDGE-Navi 側で全角化してしまうと、**当日プロファイルを切り替えても直りません。**

⚠ **半角カナ → 全角カナ変換の注意（SCP 側の実装）**：`ﾀﾞ` は「`ﾀ` + `ﾞ`」の2文字で来ます。全角化では `ダ` の1文字に結合する必要があります。半濁点（`ﾊﾟ`→`パ`）も同様。**自作の変換表を持ち、結合規則を明示すること**（実装指示書 v2 T7）。

⚠ **外字（髙・﨑・德）は漢字なのでカナ変換表の話ではありません。**案①②の UTF-8 では通り、案④の `ISO_IR 13` では表現できないため `Suppressed` になるのが正しい挙動です。

⚠ **姓名の区切りが無い／2つ以上ある場合**の扱いを決めること。推奨：区切りが無ければ全体を姓に入れ、名は空。3つ以上に分かれたら最初を姓、残りを名として結合。**いずれの場合も監査ログに残す。**

### 5-3. 文字コード案は3案（案③は作らない）

T0/S-2 で **fo-dicom が ISO 2022 のエスケープシーケンスを出力しない**ことが判明したため、案③（`ISO 2022 IR 13\ISO 2022 IR 87`）は**作りません**。根拠は `docs/設計変更メモ_v2.1.md` A-2。

用意するのは **①（初期値）／②（切り札1）／④（切り札2）** の3枚です。元データが半角カナなので、**案④は変換を挟まない**ぶん素直に出せます。案①は半角→全角の変換を1回挟みます。

⚠ 案④（`ISO_IR 13` 単独値）は fo-dicom での動作が未検証です。T7 着手前に1時間で確認してください（実装指示書 v2 §1-3）。

## 8. `WorklistEntry` へのマッピング（実装用）★1人モデル

⚠ **v1.0 にあった `WorklistUpsertRequest`（位置引数）は廃止しました。**取り違えても型エラーにならない組合せが多すぎるため、**名前付きプロパティ**にしています。

```csharp
// 骨密度ブースで受診者を受け付けたとき
await _worklistWriter.SetCurrentAsync(new WorklistEntry {
    StablePatientId = f[3],                           // 個人番号（12桁・年度不変）★
    FamilyNameKanji = SplitFullWidth(f[7]).sei,       // 漢字氏名（全角スペース区切り）
    GivenNameKanji  = SplitFullWidth(f[7]).mei,
    FamilyNameKana  = SplitHalf(f[6]).sei,            // ★半角カナのまま。全角化しない
    GivenNameKana   = SplitHalf(f[6]).mei,
    BirthDate       = f[9],                           // YYYYMMDD
    Sex             = f[8] switch { "1" => Sex.Male, "2" => Sex.Female, _ => Sex.Unknown },
    ScheduledDate   = f[1],                           // 受診日 YYYYMMDD
    AccessionNumber = BuildAccession(f[1], f[4], f[2], BmdExamCode),  // §3-3 ★CCC は要確認
    RequestedProcedureId   = null,                    // §7-2-4 で決定（当日）
    RequestedProcedureDesc = f[5],                    // コースコード "B0100：一日ドック"
    PatientSizeM    = today?.HeightCm / 100.0,        // ★当日測定値。無ければ null
    PatientWeightKg = today?.WeightKg,                // ★同上。前回値を使わない
    SourceMessageId = csvFileName,
});

// 検査が終わって受診者がブースを出たとき
await _worklistWriter.ClearCurrentAsync();
```

⚠ `f[n]` は **項番 n**（1始まり）。C# の配列は0始まりなので実装時にずれないよう注意。

⚠ **`ClearCurrentAsync` の呼び忘れが最悪の事故を作ります。**中断・スキップ・強制終了を含む**すべての画面遷移**から通るようにしてください。TTL 15分は保険であって、設計の代わりではありません。

⚠ `DeviceProfileId` / `Modality` / `ScheduledStationAe` / `ScheduledTime` / ローマ字氏名は **`WorklistEntry` から外しました**。装置・施設・検査の属性はプロファイル側（`const:`）で持ちます。
