## 1. 実施体制 — どのPCで何を動かすか

### 1-1. 結論：MWM SCP は**大徳君のPC**で動かす

| 場所 | 誰 | 役割 |
|---|---|---|
| **大徳君の自席PC** | 大徳 | **BRIDGE-Navi と MWM SCP の両方をここで動かす。**今日の実機はここ1台 |
| 東京の開発機（`C:\dev\ascube-mwm`） | 岩田（仙台からRDP） | **「正解の見本」として並走。**同じコマンドを叩いて出力を比べ、切り分けに使う |
| 仙台 | 岩田 | 画面共有で指示・確認・`docs/progress.md` への記録 |

**なぜ1台に寄せるのか。** 連携点はローカルディスク上の SQLite 1ファイルです。ネットワーク共有に置くとロックが正しく動かず破損するため禁止しています（禁止事項6）。**2台に分けた連携テストは原理的にできません。**

**なぜ大徳君の側に寄せるのか。** 1人モデルでは MWM サーバ＝BRIDGE-Navi 端末です。**今日その構成を作ること自体が、9/24 の現地設置のリハーサルになります。**現地端末も「BRIDGE-Navi の端末に mwm-scp が同居する」形です。

### 1-2. 東京の開発機に寄せない理由

- **Windows 11 Pro は対話ログオンが同時に1人。**岩田と大徳君が両方 RDP で入ると蹴り合います。
- 弥生会計と同居している機械なので、大徳君用の開発アカウントを作る話になります。今日やるには重い。

## 3. 起動時の設定（既定値のまま使うのが一番早い）

**パスはリポジトリの既定のままにしてください。** そうすれば `scripts/00_watch.ps1` などが引数なしで動きます。以下 `<clone先>` は clone した場所（例 `C:\dev\ascube-mwm`）。

cd ascube-mwm

## 6. 0件になったときの手順

**当てずっぽうで直さないでください。** 原因を名指しする機能が入っています。

```powershell
.\scripts\05_explain.ps1 -RunId <id>
```

（RunId は `01_health.ps1` で確認できます。`--audit-db` は `data\mwm-audit.db` が既定）

次の5つのどれかを、値つきで教えてくれます。

1. `CurrentEntry` が無い（誰も設定されていない）
2. TTL 切れ（`SetAtUtc` と `ExpiresAtUtc` を表示）
3. `ScheduledDate` が要求範囲外（要求範囲と実際の日付を並べて表示）
4. PatientID / PatientName の指名が一致しない（要求値と保持値を表示）
5. `DatasetBuilder` が `Suppressed`（理由を表示）

⚠ **9/28 に現地で使うのもこの手順です。今日ここに慣れておいてください。**

## 7. 文字コードの切替（当日の練習として1回やっておく）

**プロファイルを alt1 / alt2 に切り替えるのではありません。** 稼働中の `BMD_HOLOGIC.jsonc` の `charset` ブロックを書き換えて、ホットリロードさせます。

```powershell
.\scripts\switch-charset.ps1 -Plan 4    # 案④（ISO_IR 13 単独・半角カナのみ）へ
.\scripts\switch-charset.ps1 -Plan 1    # 案①（初期値）に戻す
```

- `-Plan 1` / `2` / `4`（案③は作っていません。`alt2.jsonc` が案④です——**ファイル名の番号がずれている点に注意**）
- SCP は**止まりません。**次に受け付けるアソシエーションから新しい設定で応答します。
- 検証に失敗した設定は**適用されず、稼働中の設定が維持されます**（自動ロールバック）。
- 差し替え前の内容は `config/backup/` に自動保存されます。

⚠ **9/28 に実際にこれを使う可能性があります。** 今日一度通しておいてください。
