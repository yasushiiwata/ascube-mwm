## 0. 今日の目的

> **実機Hologic APEXが、mwm-scpに対して実際にC-FINDを発行し、BRIDGE-Naviがセットした受診者1人が正しくAPEX画面に表示されること。**

これまでの開発機での確認（`docs/連携テスト手順.md`）は、自作の `mwm-scu`（ダミー装置役）で代用してきました。**今日初めて、本物の装置が相手になります。** ダミーでは再現できなかった実機固有の挙動（クエリのタイミング、画面表示、文字コードの実際の解釈）がここで初めて分かります。

⚠ **「0件」は正常応答です。** 該当者が特定できないときは0件＋Successを返します（規則16）。装置側に何も表示されなくても、まず「エラーが出ていないか」「Successで返っているか」を`admin explain-query`で確認してください。

### 1-2. ネットワーク構成

- **モダリティ側LANとインターネット側LANを分離**（同一PCの2NIC構成）。APEX自身にセキュリティ機構は無い（Conformance Statement p.69「Apex Modality does not support any specific security measures」）ため、分離自体は妥当。
- ⚠ **2NIC間のIPフォワーディングが無効になっていることを前日に確認。** 意図せずブリッジされていると分離の意味がなくなる。
- `mwm-scp`が待ち受けるのはモダリティ側NICのIPだけでよいか確認（現状は全インターフェース待受）。

### 1-3. PC構成

- **mwm-scpとBRIDGE-Naviは同一PC**（岩田が用意する機体）で動かす。連携点はローカルディスク上のSQLite1ファイルであり、ネットワーク越しの連携は不可（規則5）。
- **BRIDGE-Naviの`<TargetFramework>`を事前確認。** `Ascube.Mwm.Abstractions`/`Ascube.Mwm.Store`は`net10.0`。BRIDGE-Naviが古いframeworkのままだと`ProjectReference`が通らない。
- 当日はインターネット接続・Claude Code・大型ディスプレイが使える想定（9/16時点の岩田の準備計画）。ネットワーク承認の状況次第で変わりうるので、当日朝に再確認する。

### 1-4. 持ち物

- DCMTK（`echoscu`/`findscu`/`dcmdump`）— 自作`mwm-scu`と実装を共有しないため、規格適合の独立検証に必須（検証の注意・実装指示書）
- dumpcap（パケットキャプチャ承認が取れた場合のみ。同梱しない別インストール）
- ノートPC（mwm-scp + BRIDGE-Navi稼働用）、大型ディスプレイ

### S1：APEX側の設定

現地でAPEXの設定画面を開き、以下を確認・入力する（Conformance Statement Table 4.4-2既定値と照合）:

| 項目 | 入力値 | 備考 |
|---|---|---|
| Worklist SCP AE Title | `ASCUBE_MWM` | こちらのCalled AE。1つしか設定できない（Conformance Statement §4.4.1.2.4） |
| Worklist SCP IP/Host | mwm-scp稼働機のモダリティ側NIC IP | |
| Worklist SCP Port | `11112` | |
| Days Back / Forward | 既定60/2のまま推奨 | 変更するとテストの前提が変わるので、変更する場合は04_find.ps1側の`--emulate-apex-defaults`も合わせる |
| Scheduled Station AE Title（自動クエリ用） | 空 or 未設定 | 既定Noneのまま。設定していると絞り込みキーとして送られてくる点に注意 |

### S2：BRIDGE-Navi側の結線確認

BRIDGE-Naviから実際に受診者を1人受け付けさせ、`SetCurrentAsync`が呼ばれることを確認する。

```powershell
.\scripts\01_health.ps1
```
→「現在の受診者：あり（TTL残 mm:ss）」になっていること。**ならない場合はDBパスが両者でずれている**（`docs/連携テスト手順.md` S1の注意と同じ）。

⚠ **BRIDGE-Naviが不調・未結線の場合はここで詰まる。** その場合は §4 のフォールバックへ。

### S3：実機からのクエリ（本丸）

APEX画面で「Query」（または「Detailed Query」）ボタンを押す。

**期待**：APEXのワークリスト画面に受診者が**1件**表示される。

`00_watch.ps1`の画面と`admin explain-query`で、実際に何が起きたかを裏から確認できる:
```powershell
.\scripts\05_explain.ps1 -RunId <直近のRunId>
```

### S4：応答の中身の確認（実機画面で）

`docs/連携テスト手順.md §5` の9項目（PatientID項番3であること・PatientNameのカナ/漢字・SpecificCharacterSet・生年月日性別・AccessionNumber16桁・ScheduledDate・StudyInstanceUID不変・身長体重の省略・外字）に加え、**今日は実機画面で以下2点も目視確認する**（`docs/連携テスト手順.md §5-1`）:

| # | 確認箇所 | 期待 |
|---|---|---|
| 10 | APEX画面の「Patient Height」欄 | 事前にHologic側でマッピング設定していれば表示。していなければ空欄が正常 |
| 11 | APEX画面の「Procedure Code」欄 | 現行プロファイルは`(0040,0009)`を送っていないため空欄の想定 |

⚠ **身長の値は必ずcm表示で確認すること。** ascube-mwm内部ではDICOM上メートルに変換して送信しているため（`設計変更メモ_v2.1.md §I`）、APEX側の表示がcmに戻っているかも合わせて確認する。

### S5：患者取り違え防止（★絶対に落とせない）

1. 受診者A受付 → APEXでクエリ → **Aが表示される**
2. Aの検査完了・退室操作 → BRIDGE-NaviのClearCurrentAsyncが呼ばれる分岐を**実際の画面遷移で**確認（正常終了・中断・スキップ・強制終了の**全分岐**）
3. 受診者B受付 → APEXでクエリ → **Bだけが表示され、Aが混ざらない**

⚠ これは`PatientContinuityTests.cs`で自動テスト済み（W-01/W-02）だが、**BRIDGE-Navi側の実際の画面遷移から呼ばれるかは現地でしか確認できない。** 中断したまま次の受診者が入ってくるのが現場最悪の事故パターン。

### S6：文字コード（必要なら）

初期案①（`ISO_IR 192`）でAPEX画面の氏名表示が崩れる場合のみ:

```powershell
.\scripts\switch-charset.ps1 -Plan 4    # 案④：ISO_IR 13単独・半角カナのみ
```

SCPは止まらない。次のクエリから新設定で応答する。**外字（髙・﨑・德）を含む名前で1件試す**（案①でなければ通らない前提）。

## 3. 0件・想定外の結果への対処

**当てずっぽうで直さない。**

```powershell
.\scripts\05_explain.ps1 -RunId <id>
```

- `CurrentEntry`が無い → BRIDGE-Navi側の受付処理が`SetCurrentAsync`まで到達していない
- TTL切れ → 受付から装置クエリまで15分以上経過した（既定TTL）
- ScheduledDateが範囲外 → APEX側のDays Back/Forward設定とBRIDGE-Naviの受診日がずれている
- PatientID/PatientName不一致 → APEXが指名検索（Detailed Query）をかけている。要求値と保持値の両方が表示される
- DatasetBuilder Suppressed → 必須項目（氏名等）が欠損。監査ログに理由が残る

## 4. BRIDGE-Naviが不調・未結線のときのフォールバック

S2で詰まった場合、**BRIDGE-Navi抜きで「SCP-装置間は正常」を証明する。**

```powershell
.\scripts\07_set-current.ps1 -PatientId <個人番号12桁> -FamilyKanji <姓> -GivenKanji <名> `
    -FamilyKana <姓カナ半角> -GivenKana <名カナ半角> -BirthDate <YYYYMMDD> -Sex M|F `
    -HeightCm <身長cm> -WeightKg <体重kg> -ProcedureDesc "骨密度(駅前)"
```

APEX側でクエリして表示されれば、**問題はBRIDGE-Navi側にある**と切り分けられる。表示されなければSCP・ネットワーク・装置設定側を疑う。

片付け:
```powershell
.\scripts\08_clear-current.ps1
```

⚠ **これは本番の受診者データ投入経路ではない。** 切り分け専用。
