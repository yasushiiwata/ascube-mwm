## 1. T0 の結果と、そこから決まったこと

### 1-1. 結果

| ID | 結果 | 内容 |
|---|---|---|
| **S-1** | **○** | .NET 10 + fo-dicom 5.2.6 で最小 SCP が動作。`echoscu` / `findscu` の両方から Success。**.NET 10 で進める。退避不要** |
| **S-2** | **△／一部×** | `ISO_IR 192`（UTF-8）は往復一致。**`ISO 2022 IR 13\ISO 2022 IR 87` は fo-dicom がエスケープシーケンスを出力せず、規格不適合なバイト列になる。**DCMTK 側が拒否して発覚 |
| **S-3** | **○** | `AddFellowOakDicom()` の後に **`AddNetworkManager<T>()`** で自作 NetworkManager を差し込める。全送受信バイトを捕捉できる見込み。**透過 TCP proxy（案③）は不要** |
| **alt4** | **○** | 案④（`ISO_IR 13` 単独値）。半角カナ（濁点・半濁点・長音・中点・30文字級）が JIS X 0201 の `0xA1`〜`0xDF` の1バイトで出力され、エスケープシーケンスも出ず、DCMTK `dcmdump` が警告なく読める |

⚠ alt4 の異常系（漢字を混ぜる）で新たな不具合を発見：`ISO_IR 13` 指定時に漢字を渡すと、fo-dicom は無警告で CP932 相当のバイト列を書き、**自分ではそれを正しく読み戻してしまう**（往復検証が合格してしまう）。DCMTK は読み込みを拒否して検出できた。**文字コードの往復検証に fo-dicom の decoder を使ってはならない**（CLAUDE.md 規則19。§5 T7 に反映済み）。

⚠ 参考：ISO 2022 で本来現れるべきエスケープシーケンスは、**漢字への切替が `1B 24 42`（ESC $ B ＝ JIS X 0208 ／ `ISO 2022 IR 87`）**、**復帰が `1B 28 4A`（ESC ( J ＝ JIS X 0201 Roman ／ `ISO 2022 IR 13` の G0）**です。`1B 28 42`（ESC ( B）は ASCII への復帰で、`ISO 2022 IR 6\ISO 2022 IR 87` の組合せのときの値です。**組合せによって復帰シーケンスが違う**ので、`docs/TODO.md` の記述もあわせて直してください。

⚠ S-2 は「自作 SCU では気づけなかった」種類の不具合です。自作 SCU も同じ fo-dicom なので、壊れたバイト列をそのまま読み戻して「往復一致」に見えました。**DCMTK が別実装であることが役に立った実例**なので、以後も規格適合の判定は必ず DCMTK で行ってください。

### 1-2. 文字コード：案③を作らない（重要な設計判断）

文字コードの選択肢は当初4案ありました。S-2 の結果、**梯子を ①→②→④ に組み替え、③は作りません。**

| 案 | 内容 | 状態 |
|---|---|---|
| **①（初期値）** | `ISO_IR 192`（UTF-8）／PN 第1群＝全角カナ、第2群＝漢字、第3群＝全角カナ | **本命。実装する** |
| **②** | `ISO_IR 192`／PN 第1群＝空、第2群＝漢字、第3群＝全角カナ | 実装する（当日の切り札1） |
| **③** | `ISO 2022 IR 13\ISO 2022 IR 87` | **作らない。**fo-dicom で正しいバイト列が出せない |
| **④** | `ISO_IR 13` 単独／**半角カナのみ・漢字を送らない** | 実装する（当日の切り札2）。**要検証（§1-3）** |

**③を作らない根拠**

1. 自前 `byte[]` エンコーダの実装に **いま作るなら 2〜3日**かかる。残り10営業日の 20〜30%。
   （9/28 の pcap で装置の実挙動が分かった後なら **1〜2日**。仕様を当てずっぽうで決めなくてよいぶん安い）
2. ③が必要になるのは「**装置が UTF-8 を拒否し、かつ漢字が必須**」の場合のみ。
   APEX 5.6 の適合性宣言は `ISO_IR 192` と `ISO_IR 13` の**両方を宣言**しており、**装置自身が UTF-8 を生成する**。この条件が同時に成立する確率は低い。
3. 漢字が表示できなくても、**④（半角カナ単独）で受診者の同定はできる。**検査が止まらない。
4. 万一 9/28 に UTF-8 が通らなかった場合、**pcap に装置の実挙動が全部残る。**それを見てから作れば、当てずっぽうで作るより速く確実。

⚠ **この判断は「やらない」ことの記録です。**後日「なぜ ISO 2022 に対応していないのか」と問われたときのために、`docs/TODO.md` に**自前エンコーダ（見積 1〜2日）を残課題として明記**してください。

### 1-3. 実装前にやる確認（1時間）

**案④（`ISO_IR 13` 単独値）が fo-dicom で正しく出るか**を、T7 の着手前に spikes で確認してください。

- `SpecificCharacterSet = "ISO_IR 13"` を設定し、PN に**半角カナのみ**を入れて出力
- **判定は16進で行う。**`Format-Hex` または `dcmdump +U8`。コンソールが CP932 なので画面表示で判定してはいけない（`docs/TODO.md` 参照）
- 期待：半角カナが **JIS X 0201 の 0xA1〜0xDF** で出る。エスケープシーケンスは**現れない**（単一バイト集合なので不要）
- × だった場合：**①と②だけで当日に臨む。**④のプロファイルは配らない

## 2. `CLAUDE.md` に追記する規則

リポジトリ直下の `CLAUDE.md` の「絶対に守る規則」に、**次の4項目を追記**してください（既存1〜14 はそのまま）。

```markdown
15. **fo-dicom は ISO 2022 のエスケープシーケンスを出力しない（T0/S-2 で確認）。**
    `SpecificCharacterSet` に `ISO 2022 IR 87` / `ISO 2022 IR 13` を含む値を設定しても
    正しいバイト列にならない。**ISO 2022 系のプロファイルを作らない・配らない。**
    使えるのは `ISO_IR 192`（UTF-8）と `ISO_IR 13`（半角カナ単独）だけ。
    ⚠ 規則7（`ISO 2022 IR 87` を単独値にしない）は規格上の話として引き続き有効だが、
    そもそも ISO 2022 系を使わないので実務上は発生しない。

16. **ワークリストに載るのは常に当日の1人だけ（1人モデル）。**
    MWM サーバは BRIDGE-Navi の端末と1対1で対応する。
    **「該当者が特定できないときは0件を返す。古い1人を返さない。」**
    前の受診者を消し忘れて次の人の検査に載せるのが、この構成で最悪の事故。
    ⚠ `fallbackToAllTodayWhenNoActive` のような「とりあえず今日の一覧を返す」機能を作らない。

17. **当日の身長・体重は、当日測定した値だけを送る。**
    依頼電文には前回・前々回の値しか入っていない。
    未測定ならタグごと省略する（`onMissing: omit`）。前回値を今日の値として送らない。
    ⚠ ブースの巡回順は誘導アルゴリズムが決めるため、骨密度が身長体重より
    先になる場合がある。「未測定なら省略」は必ず通る経路。

18. **依頼電文の項番3（個人番号・12桁）と項番4（受診番号・5桁）を取り違えない。**
    PatientID に入れるのは**項番3**。項番4 は毎回変わるので、入れると同じ人が
    毎年別人として登録され、骨密度の経年比較が壊れる。**1年後まで発覚しない。**
```

## 3. 主要インターフェース（`Ascube.Mwm.Abstractions`）★1人モデルで全面改訂

### 3-1. BRIDGE-Navi 本体が使うもの

v1 の `UpsertAsync` / `SetActiveAsync` / `ClearActiveAsync` は**廃止**します。1人モデルでは「今この端末に載っている人」を差し替えるだけなので、次の3つで足ります。

```csharp
namespace Ascube.Mwm.Abstractions;

public interface IWorklistWriter
{
    /// 今この端末のワークリストに載せる受診者を1人だけ設定する（既存は置き換わる）。
    /// StudyInstanceUID はこの中で1回だけ採番される。
    Task SetCurrentAsync(WorklistEntry entry, CancellationToken ct = default);

    /// ワークリストを空にする。以後の C-FIND は 0件 + Success を返す。
    Task ClearCurrentAsync(CancellationToken ct = default);

    /// 現在載っている受診者（無ければ null）。画面表示・自己診断用。
    Task<WorklistEntry?> GetCurrentAsync(CancellationToken ct = default);
}

public sealed record WorklistEntry
{
    public required string StablePatientId { get; init; }   // 項番3 個人番号12桁（年度不変）★
    public string? FamilyNameKanji  { get; init; }          // 項番7 全角スペースで分割
    public string? GivenNameKanji   { get; init; }
    public string? FamilyNameKana   { get; init; }          // 項番6 半角スペースで分割・半角のまま渡す
    public string? GivenNameKana    { get; init; }
    public string? BirthDate        { get; init; }          // 項番9 "YYYYMMDD"
    public Sex     Sex              { get; init; }          // 項番8 1→Male, 2→Female, それ以外→Unknown ★
    public required string ScheduledDate { get; init; }     // 項番1 "YYYYMMDD"
    public string? AccessionNumber       { get; init; }
    public string? RequestedProcedureId  { get; init; }
    public string? RequestedProcedureDesc{ get; init; }     // 項番5 コースコード
    public double? PatientSizeM     { get; init; }          // ★当日値。未測定なら null
    public double? PatientWeightKg  { get; init; }          // ★当日値。未測定なら null
    public string? SourceMessageId  { get; init; }          // 依頼電文のファイル名など
}

public enum Sex { Unknown = 0, Male, Female, Other }
```

⚠ **性別が `1` でも `2` でもないときに `Other`（`O`）を入れてはいけません。**`O` は「その他」という**実在の値の主張**であり、値の捏造にあたります（規則4）。空欄・未定義値は `Sex.Unknown` とし、**`(0010,0040)` PatientSex は空値で返します。**MWM の PatientSex は Type 2 なので、長さ0で返すことが規格上正しい扱いです。`Other` を使うのは、依頼電文が明示的に「その他」を意味する値を持っていた場合だけです。

⚠ **位置引数の record にしないこと。**v1 は位置引数でしたが、`StablePatientId` と `AccessionNumber`、`FamilyNameKana` と `FamilyNameKanji` のような**取り違えが起きても型エラーにならない**組合せが多すぎます。このプロジェクトで最も危険な間違いなので、**名前付きプロパティで書かせる**設計にします。

### 3-2. DI 登録（BRIDGE-Navi 本体側）

```csharp
public sealed class MwmStoreOptions
{
    public required string DatabasePath    { get; set; }   // ローカルディスクのみ。共有不可
    public required string DeviceProfileId { get; set; }   // "BMD_HOLOGIC"
    public TimeSpan CurrentTtl { get; set; } = TimeSpan.FromMinutes(15);
}

// Ascube.Mwm.Store が提供する拡張メソッド
public static IServiceCollection AddAscubeMwmStore(
    this IServiceCollection services, Action<MwmStoreOptions> configure);
```

**`CurrentTtl`（既定15分）は消し忘れの保険です。**設定してから TTL が経過したら、SCP は 0件を返します。ClearCurrentAsync を呼び忘れても、前の人が延々と載り続けることはありません。

⚠ **TTL は書き込み側（`MwmStoreOptions.CurrentTtl`）とプロファイル側（`visibility.currentTtlMinutes`）の2か所に現れます。優先順位を次のとおり固定してください。**

- 書き込み側は `SetCurrentAsync` の時刻に `SetAtUtc` と `ExpiresAtUtc`（= `SetAtUtc` + `CurrentTtl`）を記録する。
- **SCP 側の判定は `min(ExpiresAtUtc, SetAtUtc + プロファイルの currentTtlMinutes)`。短いほうが勝つ。**
- こうすると、当日プロファイルのホットリロードで TTL を**短くする**ことはできる（BRIDGE-Navi を再起動せずに安全側へ倒せる）が、長くはできない。**安全側にだけ動く。**

## 4. BRIDGE-Navi 本体側の改修

### 4-1. 依頼電文の取り込み（受付時）

```csharp
// ⚠ 起動時に1回。呼ばないと CP932 が読めない
Encoding.RegisterProvider(CodePagesEncodingProvider.Instance);
var enc = Encoding.GetEncoding(932);

// 1irai<YYYYMMDDhhmmss>.csv / ヘッダなし / 1行1受診者 / 237フィールド
// f[n] は項番 n（1始まり）。C# 配列は0始まりなのでずらさないこと。
```

| 項番 | 内容 | `WorklistEntry` |
|---:|---|---|
| 1 | 受診日 YYYYMMDD | `ScheduledDate` |
| 2 | 受診区分（2桁） | AccessionNumber の材料 |
| **3** | **個人番号 12桁（年度不変）** | **`StablePatientId`** ★ |
| 4 | 受診番号 5桁 | AccessionNumber の材料。**PatientID に入れない** |
| 5 | コースコード `B0100：一日ドック` | `RequestedProcedureDesc` |
| 6 | カナ氏名（半角カナ・半角スペース区切り） | `FamilyNameKana` / `GivenNameKana`（**半角のまま渡す**） |
| 7 | 漢字氏名（全角・全角スペース区切り） | `FamilyNameKanji` / `GivenNameKanji` |
| 8 | 性別 1:男 2:女 | `Sex`（それ以外は `Unknown`。`Other` にしない） |
| 9 | 生年月日 YYYYMMDD | `BirthDate` |
| **59** | **骨密度(駅前) フラグ** | **`1` の受診者だけを対象にする** |

⚠ **カナは半角のまま `WorklistEntry` に渡してください。**全角化するかどうかは文字コード案（①②④）によって変わるので、**SCP 側（T7 の PnEncoder）で決めます。**BRIDGE-Navi 側で変換すると、当日プロファイルを切り替えても直りません。

⚠ **項番60（骨密度・山科）は見ません。**施設は駅前で確定、装置は1台です。

### 4-2. 受診者の切り替え（ブース入退場）

```csharp
// 骨密度ブースで受診者を受け付けたとき
await _worklistWriter.SetCurrentAsync(new WorklistEntry {
    StablePatientId = row.PersonId,        // 項番3
    FamilyNameKanji = kanji.sei,  GivenNameKanji = kanji.mei,
    FamilyNameKana  = kana.sei,   GivenNameKana  = kana.mei,   // 半角のまま
    BirthDate       = row.Birthday,
    Sex             = row.SexCode switch { "1" => Sex.Male, "2" => Sex.Female, _ => Sex.Unknown },
    ScheduledDate   = row.ExamDate,
    AccessionNumber = BuildAccession(row.ExamDate, row.VisitNo, row.VisitType, BmdExamCode),
    RequestedProcedureDesc = row.CourseCode,
    PatientSizeM    = today?.HeightCm / 100.0,   // ★当日測定値。無ければ null
    PatientWeightKg = today?.WeightKg,           // ★同上。前回値を使わない
    SourceMessageId = csvFileName,
});

// 検査が終わって受診者がブースを出たとき
await _worklistWriter.ClearCurrentAsync();
```

⚠ **`ClearCurrentAsync` の呼び忘れが最悪の事故を作ります。**画面遷移の分岐（中断・スキップ・強制終了）すべてから通るようにしてください。TTL 15分は保険であって、設計の代わりではありません。

### 4-3. 未解決：骨密度の AccessionNumber

依頼電文の AccessionNo 枠（項番130〜149）に**骨密度の枠がありません。**規則自体は実データで検証済みです。

```
YYMMDD + BBBBB(受診番号) + AA(受診区分) + CCC(検査識別)
例: 2607010011010053 = 260701 + 00110 + 10 + 053(胸部Ｘ線)
```

| 対応 | 内容 |
|---|---|
| **短期（9/28 用）** | 同じ規則で BRIDGE-Navi が自前生成する。`BmdExamCode`（CCC 3桁）は**設定値として外に出す**（コードに直書きしない） |
| **本筋** | ヘルゼアに予備2〜7 の1枠を骨密度へ割り当ててもらう |

⚠ **`BmdExamCode` の正しい値をヘルゼアに確認するまで、暫定値であることをログと設定コメントに明記してください。**将来ヘルゼアが正式に払い出したときに衝突します。

### T2：SQLite ストア＋UID 採番【9/7〜9/8】★1人モデルで簡素化

開発計画 v2 付録A の DDL のうち、**`ActiveContext` を `CurrentEntry` に置き換え**ます。

```sql
PRAGMA journal_mode = WAL;
PRAGMA busy_timeout = 5000;

-- 1人モデル：この端末に「今」載っている受診者。常に0行か1行。
CREATE TABLE CurrentEntry (
  Singleton      INTEGER PRIMARY KEY CHECK (Singleton = 1),   -- ★常に1行に強制
  WorkItemId     TEXT NOT NULL,
  DeviceProfileId TEXT NOT NULL,
  SetAtUtc       TEXT NOT NULL,
  ExpiresAtUtc   TEXT NOT NULL                                -- SetAtUtc + CurrentTtl
);
```

`Patient` / `WorkItem` / `UidAllocation` / `AuditCFind` / `AuditCFindItem` は付録A のまま。**`WorkItem` は履歴として残します**（監査と、同じ人が同日に再測定するときの UID 再利用のため）。

- `IWorklistWriter.SetCurrentAsync`：**1トランザクション**で `Patient` upsert → `WorkItem` upsert → `UidAllocation` で StudyInstanceUID を採番 → `CurrentEntry` を差し替え（`INSERT ... ON CONFLICT(Singleton) DO UPDATE`）。
- `ClearCurrentAsync`：`DELETE FROM CurrentEntry`。**`WorkItem` は消さない。**
- `IUidAllocator`：`2.25.` + `Guid.NewGuid()` の128ビットを整数として10進表記（先頭ゼロ除去）。
- SCP 側は `Mode=ReadOnly` かつ **`PRAGMA query_only=1`**（WAL の `-shm` に書けないと開けないため、ファイル権限での読み取り専用にはしない）。

**受入条件**
- 同じ `WorklistEntry` を100回 `SetCurrentAsync` しても `WorkItem` の行が増えず、**StudyInstanceUID が変わらない**。
- **`SetCurrentAsync` を A → B の順で呼んだあと、`GetCurrentAsync` が B だけを返す**（A が残らない）。

### T7：PnEncoder（文字コード3案）【9/15】★案③を削除

- `charset.patientName` の群割当（`none`/`kanaHalf`/`kanaFull`/`romaji`）に従って PN を組む。
- **`SpecificCharacterSet` を DicomDataset に最初に設定する**（規則6）。
- **半角カナ → 全角カナ変換は自前の変換表**を持つ。⚠ `ﾀﾞ` は「`ﾀ` + `ﾞ`」の2文字で来る。全角化では `ダ` の1文字に**結合**する。半濁点（`ﾊﾟ`→`パ`）も同様。長音 `ｰ`→`ー`、中点 `･`→`・`、句読点類も表に含める。
  ⚠ `ISO_IR 13`（JIS X 0201）では `0x5C` は円記号（¥）、`0x7E` はオーバーライン（‾）であって
  バックスラッシュ・チルダではない。DICOM の PN では `0x5C` が多値の区切りなので、
  氏名データに `0x5C` を通さないこと。
- **外字（髙・﨑・德）は漢字なのでカナ変換表の対象外。**これらは**往復検証**の側で扱う（案①②の UTF-8 では通り、案④の `ISO_IR 13` では表現できないので `Suppressed` になるのが正しい挙動）。テストデータに必ず入れること。
- **生成したバイト列を直接検査する。fo-dicom の自己再読込に頼らない（規則19）。**
  - `ISO_IR 13`：PN の全バイトが `0x20`〜`0x7E` または `0xA1`〜`0xDF` に収まること。
    1バイトでも外れたら `Suppressed`。
    ⚠ CP932 の漢字は先頭バイトが `0x81`〜`0x9F` / `0xE0`〜`0xEF` なので、この検査で必ず捕まる。
  - `ISO_IR 192`：`UTF8Encoding(false, throwOnInvalidBytes: true)` で decode し、
    例外または `U+FFFD` が出たら `Suppressed`。
- **姓名の区切りの扱い**：区切りが無ければ全体を姓に入れて名は空。3つ以上に分かれたら最初を姓・残りを結合して名。**いずれも監査ログに残す。**
- プロファイルは **①②④の3枚**（`BMD_HOLOGIC` / `.alt1` / `.alt2`）。

**受入条件**
- N-14 / N-15 / E-12 が通る。
- **3案すべてで `mwm-scu preview` が期待バイト列を出す**（16進で目視確認できる）。
- **判定は必ず16進で行う。**コンソールは CP932 なので画面表示で判定しない。
- **DCMTK（`dcmdump +U8`）で3案すべてが読める。**fo-dicom で読めるだけでは受入としない（S-2 の教訓）。
- 案④で漢字を渡したときに `Suppressed` になる（**代替文字で無言に化けない**）。
- 案④のプロファイルで漢字を渡すと `Suppressed` になり、**CP932 のバイト列が出力されない**
  （生バイトを検査して `0x81`〜`0x9F` / `0xE0`〜`0xEF` が現れないことを確認する）。
- 上の判定が **fo-dicom を経由せずに**行われていること（テストコードで生バイトを直接見る）。

## 6. やってはいけないこと（禁止事項）★4項目追加

| # | 禁止 | 理由 |
|---|---|---|
| 1 | C-FIND のたびに StudyInstanceUID を採番する | PACS で1検査が複数スタディに分裂。運用開始後に発覚 |
| 2 | 0件で Error / `QueryRetrieveUnableToProcess` を返す | 装置画面にエラーが出る |
| 3 | `OnConnectionClosed` で例外を再スローする | リスナが道連れになり「二度と繋がらない」 |
| 4 | 患者項目をダミー値で補完する | ダミーの患者情報が画像に焼き付く |
| 5 | SCP から SQLite に書き込む | 連携の一方向性が壊れ、障害解析ができなくなる |
| 6 | SQLite をネットワーク共有に置く | ロックが正しく動作せず破損する |
| 7 | `AccessionNumber` を `WorkItem` の主キーにする | 年度で重複しうる／未採番の検査を保持できない |
| 8 | `SpecificCharacterSet` を後から設定する | 符号化が壊れる。当日最も時間を溶かす形で現れる |
| **9** | **`ISO 2022` を含む `SpecificCharacterSet` のプロファイルを作る／配る** | **fo-dicom がエスケープシーケンスを出さない（T0/S-2）。規格不適合なバイト列になる** |
| 10 | 検証に失敗した設定を適用する | 現場の1文字のミスが検査停止に直結 |
| **11** | **「該当者不明のときに今日の一覧を返す」フォールバックを作る** | **1人モデルでは他人を返すことになる。患者取り違えに直結** |
| **12** | **前回・前々回の身長体重を当日値として送る** | 値の捏造。規則4 違反。骨密度の結果に影響する |
| **13** | **項番4（受診番号）を PatientID に入れる** | 同じ人が毎年別人になり、経年比較が壊れる。1年後まで発覚しない |
| 14 | fo-dicom を fork・改変する | 保守不能になる |
| 15 | GPL コードを取り込む／Npcap を同梱する | ライセンス違反 |
| 16 | tool 出力から読んだ内容を再入力してファイルを書き直す | 切り捨てられている可能性がある |
| 17 | 自作 SCU だけで「規格として正しい」と判定する | 同じ fo-dicom なので同じバグを再現する（**S-2 で実際に起きた**） |
| 18 | `wlmscpfs` とバイナリ完全一致を期待する | 正常でも異なる。意味比較で行う |
| 19 | GUI を作る | 10営業日では他の必須項目を押し出す |
